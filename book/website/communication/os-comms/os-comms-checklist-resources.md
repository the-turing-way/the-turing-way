# Checklist and Resources

## Checklist

Use this checklist once you have decided how your project will communicate.
It turns the guidance in {ref}`cm-os-comms-channels` and {ref}`cm-os-comms-issue-tracking` into action points.

### Communication Channels

- Choose channels that your community can find, join and leave easily, and list them in one place, such as your README or website, so that people do not have to guess where conversations happen.
- Decide whether each channel is moderated and who is responsible for moderation, because under-represented groups may not participate in a channel that is a free-for-all.
- Check how noisy each channel is and whether members can control or filter notifications, so that taking part does not become a burden.

### Issue Tracking

- Record bugs, feature requests and community tasks as issues that the community can see, and describe in your contributing guidelines what belongs in an issue.
- Keep issues in the repository that holds the code they refer to, and if you also use a centralised board, link to it from every repository and explain why it is separate.
- Label issues that are suitable for newcomers, such as `good first issue`, and point to them in your documentation so that the board shows the project is active and open to contributions.

## What to Learn Next

- {ref}`cl-new-community-guide` explains how to plan a community around the channels you choose, including contribution guidelines, a code of conduct and a leadership structure.
- {ref}`ch-coc` describes what a code of conduct should contain and how to handle reports, which is what makes moderation credible rather than arbitrary.
- {ref}`cl-maintain-review` covers what happens when people begin contributing through those channels: reviewing, merging and maintaining contributions.

## Further Reading

- [GitHub Docs: Setting up your project for healthy contributions](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions): A checklist of the files that support communication, such as README, CONTRIBUTING, CODE_OF_CONDUCT and issue templates.
- [Open Source Guides: Building Welcoming Communities](https://opensource.guide/building-community/): Practical advice on where to hold conversations, how to moderate them and how to keep newcomers involved.
- [Contributor Covenant](https://www.contributor-covenant.org/): A widely adopted code of conduct, with enforcement guidelines, that you can adapt for the spaces you set up.
- [GitHub Docs: About issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/about-issues): An introduction to issues, labels and project boards for teams choosing an issue tracker.
